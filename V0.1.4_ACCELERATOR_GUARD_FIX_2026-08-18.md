# v0.1.4 accelerator guard and NPU preservation

## What changed

- Restored the user-selectable Qualcomm QNN HTP/NPU experimental backend.
- Kept the known process-crashing QNN DSP vector-estimator route disabled.
- Kept HTP Encoder/VE disabled; only the HTP/FP16 Vocoder probe is retained.
- Added one automatic CPU/XNNPACK recreation and retry when accelerator
  initialization or the first un-emitted chunk fails.
- Added an accelerator-only audio quality guard. It rejects finite output when
  both peak and RMS are implausibly low, or when output is implausibly large.
- Added requested backend, active backend, and fallback reason to every profile.
- Kept CPU/XNNPACK as the default.

## Why the finite-output guard is required

The supplied Helio G99 NNAPI run completed with end-to-end RTF 2.148 but its
output had peak 0.029 and RMS 0.002 and sounded like wind rather than speech.
The previous NaN/Inf-only guard could not detect this failure.

## What this does not claim

The public FP32 Supertonic graphs are not full-NPU compatible. The restored NPU
entry is a safe development/probe path, not a performance claim. Useful full
HTP residency still requires a validated quantized graph or QNN context binary.

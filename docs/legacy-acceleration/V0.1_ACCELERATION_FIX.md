# v0.1 acceleration integration changes

The earlier STRICT build failed at `CreateCompiledModel(status=504)` for both GPU and Qualcomm NPU on the first `duration` graph.

This revision corrects two integration problems before drawing conclusions about model op support:

1. **Qualcomm CompiledModel JIT packaging**
   - Previous build supplied a standalone Qualcomm `qnn-runtime` Maven AAR but did not install the complete LiteRT JIT dispatch/compiler runtime set expected by CompiledModel.
   - `setup.sh` now installs the official LiteRT `litert_npu_runtime_libraries_jit.zip` bundle matching the LiteRT runtime and runs its Qualcomm fetch helper.
   - The LiteRT Qualcomm dispatch/compiler libraries, QNN HTP host libraries, and version-specific HTP DSP skel/stub libraries are packaged together.

2. **Android GPU driver visibility**
   - The app already packaged `libLiteRtClGlAccelerator.so` but only declared `libOpenCL.so`.
   - The manifest now also declares optional `libvndksupport.so`, `libOpenCL-car.so`, and `libOpenCL-pixel.so` so Android vendor OpenCL discovery is not unnecessarily blocked.

STRICT behavior remains intentional: if LiteRT still cannot compile a graph fully for the selected accelerator, it reports failure instead of silently running a mixed CPU/accelerator graph.
